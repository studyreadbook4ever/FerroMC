## 이 프로젝트를 진행한 이유

2026년 10월 16일, 졸업예정자 뽑는 채용공고들 지원할 곳 다 지원하니까 급속도로 뇌가 썩어들어가는 기분이 들었다. AI가 너무 빠르게 발전하고 있고 그 AI를 활용하는 힘을 최대한 깎아야한다는 집념 때문에 이번 여름방학 제대로 쉬지를 못하고 코덱스만 매일 붙잡고 있던 것 같다. 그러다가 하나의 Phase가 끝나니 급속도로 도파민 터지던게 끊기고 머리가 안 돌아가는 기분을 느꼈다. 다음달에 면접 다니는 새로운 Phase에 최선으로 임하기 위해선 지금 공격적으로 빡세게 쉬어줘야겠다는 생각이 들었다. 그래서 진행한 프로젝트가 바로 이 프로젝트이다.

맨날 학창시절에 머리는 좋은데 따로 공부에 흥미는 못 느끼는 친구들 보면 하나같이 "아 시험만 안 보면 공부 열심히 할텐데" 이런 얘기를 하더라. 그 얘기를 어렸을 때는 공감을 못했었는데 지금 강하게 느껴지더라.. 컨디션 안 좋다고 해서 쉬면 오히려 스트레스가 몰려와서 컨디션이 더 안 좋아지는 최악의 악순환에 빠져버림.. 그 지점에서 재밌게 즐기면서 진행한 바이브코딩 프로젝트다. 

프로젝트의 아이디어를 따온 지점은 크게 2가지가 있다. 첫 번째로 작곡해주는 AI들이 인간에게 통찰을 대놓고 안 주지만 그래도 작곡하나는 기가 막히게 잘해서 사람들의 논쟁거리에 계속해서 오르는 것 같다.(아마 AI어쩌고로 이뤄지는 수백가지 사회 변화중 가장 비개발자들이 많이 체감하는 지점이 아닐까 싶다) 과거 레이 커즈와일이 "미래 ai시대 인간은 직업 개념이 여러개일 것이다. 취미 느낌으로 긱워크를 수십개 자아실현의 일환으로 하는 삶을 살 것이다" 라고 얘기했던게 생각이 났다.

AI 얼리어답터 컴공4학년의 시점에서 봤을 때 이 말이 크게크게 와닿지는 않지만 커즈와일이 ai시대를 제일 잘 맞춘 과거사람이란 점에서 중요하게 새겨들어야 할 말인 것 같다. 이런 미래를 생각하는 관점에서, 지금 ai로 작곡하는건 인간에게 아무런 통찰을 주지 않는다는 점에서 미래인간스럽지 못한 것 같다. ai가 'PUBLIC ENEMY'급으로 초고퀄의 음악을 밥먹듯 매초 뽑아내면 그땐 말이 달라지겠지만 일단 2026년 10월 지금시점에는 ai음악이 바람직하지 못하다고 생각한다. 이 문제를 해결할 수 있는 인간이 **본인 주도로 + ai의 도움을 받아서** 음악을 잘 뽑아낼 수 있도록 몬테카를로 탐색으로 음을 뽑아내기 좋은 인간적인 앱을 하나 취미로 찍어내봤다.

두 번째로 일론머스크가 X에서 "바둑에서 이상적인 수는 바둑의 정형화된 패턴상 한정돼있는거 아님?" 식으로 어그로 끌면서 중국인들이랑 논쟁하는걸 봤는데 이는 '이번생엔 풀리기 힘든 난제'에 가까운 문제 같다. 지금 당장 바둑을 하는 사람들은 전부 '바둑에서 필승수는 절대 나올 수 없고 몬테카를로 탐색하면 무수히 많은 묘수가 나온다'라고 강하게 주장하고 거의 이게 '정배'로 보이지만 역배가 터질 수도 있는거고 여기서 중요한건 저 논쟁의 **결**인 것 같다. 

몬테카를로 탐색을 머신러닝 기반으로 할 때 '이거 굳이 연산할 필요 없을듯?' 얘기하는게 사실은 그 안에 전역최적해가 있을 수 있는건 놓쳐선 안 될 중요한 개념이다. 이 중요한 개념을 무시하면서, 일론이 바둑하는 사람들 긁어가면서 말하고자 하는 얘기는, 설령 컴퓨팅 자원이 무한에 가까운 시대가 와도 굳이굳이굳이굳이 머신러닝기법을 통해 얻을 수 있는 효율성을 포기하면서 자원을 낭비할 필요가 없다는 얘기다. 

위 바둑논쟁과 일맥상통하는게 '작곡'이라고 생각된다. 화성학 이론과 조화, 과거 히트곡 데이터도 결국 국소최적해이고, 마찬가지로 작곡모델들도 이 국소최적해 기반 히트곡들 데이터로 만들어진 '정형화된 패턴에 입각한' ai이다. 그래서 사람이 '반ai적으로' 작곡할 때 필요한게 npu를 활용해 난수음을 뽑아내는거란 생각이 들었다. 그래서 이 FerroMC 어플리케이션을 개발해보았다.

# FerroMC

Galaxy S24 Ultra에서 NPU로 짧은 음 조합을 탐색하는 Android 앱입니다. 음정과 함께 각 음의 **TONE·DECAY·DRIVE·VELOCITY**를 생성하고, 마음에 드는 결과를 [Ferro](https://github.com/studyreadbook4ever/Ferro)에서 이어 편집할 수 있습니다.

다운로드 APK는 **ARM64 Galaxy S24 Ultra용 디버그 빌드**입니다. v0.1.1은 기존 설치본과 같은 개발용 키로 서명해 앱을 삭제하지 않고 업데이트할 수 있습니다. APK 파일명은 `FerroMC.apk`입니다.

**v0.1.1 검증:** JVM 테스트 48개, 실물 S24 Ultra의 저장 한도·NPU 생성·기록 화면 테스트 4개를 통과했습니다. 기존 기록을 유지한 업데이트와 배포 APK의 설치 해시도 확인했습니다. 모델·Ferro 호환성과 이전 버전의 상세 검증은 [검증 상태](research/validation.md)에 기록했습니다.

## 사용

1. **음 생성**을 눌러 2~4개 음을 만들고 **재생**으로 다시 듣습니다.
2. **과거 생성기록 보기**에서 듣기·좋아요·삭제를 할 수 있습니다. 좋아요는 위에 모이고 처음에는 최근 일반 기록이 보입니다. **좋아요를 누르지 않은 기록은 최근 100개까지** 보관하며, 초과하면 가장 오래된 기록부터 자동 삭제합니다. 좋아요 기록은 별도로 보관해 이 제한으로 삭제하지 않습니다.
3. 좋아요를 누른 결과의 **.ferro 내보내기**를 선택합니다. 저장한 파일은 사용자가 직접 PC로 옮깁니다.
4. Ferro에서 음정·velocity와 음별 tone·decay·drive를 편집합니다.

앱은 정확한 생성값을 기기에 저장합니다. 재생할 때 모델을 다시 실행하지 않으며 좋아요로 재학습하지 않습니다. 미리듣기는 Ferro의 Saw DSP를 Java로 이식해 사용하고, 앱 음량과 출력 경로는 별도입니다. 파일은 편집 가능한 프로젝트이며 별도 WAV나 메타데이터를 내보내지 않습니다.

## 모델과 실행

| 모델 | 파라미터 | 입출력 |
|---|---:|---|
| 음정 MLP `256 → 128 → 128 → 256` | 82,432 | `float32[16,256] → [16,256]` |
| 음색 MLP `32 → 64 → 64 → 64` | 10,432 | `float32[16,32] → [16,64]` |
| 합계 | **92,864** | 정적 U8/U8 QDQ ONNX |

두 모델 모두 합성 데이터와 무작위 초기 가중치로 학습했습니다. 사전학습 모델, 음악 데이터셋, 조성·코드 이름·화음 진행 규칙을 사용하지 않습니다. 약한 음향 거칠기 지표로 확률을 조정하며, 이 지표는 청감이나 창의성을 입증하지 않습니다. 음정 모델은 과거의 세 배음 기준음을, 음색 모델은 Ferro Saw의 근사 스펙트럼을 학습에 사용합니다.

신경망은 Qualcomm HTP V75를 지정하고 CPU 그래프 폴백을 차단합니다. 두 모델의 실제 초기 실행 프로파일을 확인해야 생성이 활성화됩니다. 입력 준비·확률 샘플링·오디오 합성은 CPU에서 실행합니다. HTP를 준비하지 못하면 생성을 막고, 저장된 기록의 재생과 내보내기는 제공합니다. 기기에서 학습하지 않습니다.

## 빌드와 재현

JDK 17, Android SDK 35가 필요합니다. 패키지는 `dev.ferro.seed`, 대상은 ARM64 Snapdragon 8 Gen 3 / HTP V75입니다.

```sh
python3 tools/setup_qnn_runtime.py
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다. [재현 절차](research/reproduction.md)에 학습·실물 기기·Ferro 검증 명령이 있고, [NPU 통합 설명](research/npu-integration.md)에 런타임 조건을 기록했습니다.
